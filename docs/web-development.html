12. Web development

How websites work, using the one you are reading.

Learning intentions

  • see that a website is made from HTML, CSS and JavaScript
  • read real HTML, CSS and JavaScript from this site
  • see how Python can write web pages
  • follow a simple design process for a digital outcome
  • publish a static website

Success criteria: I can…

  • name the job of HTML, CSS and JavaScript
  • make a small web page with headings, links, a list and a table
  • explain what makes a page accessible
  • describe how I would test and improve my page

You are reading a web project

This learning site is a static website: a folder of files that a browser just opens. No database and no server program. That makes it easy to host for free on GitHub Pages. A website is built from three languages that work as a team:

LanguageJobLike a…
HTMLthe structure and the content: headings, paragraphs, links, tablesthe skeleton and the words of a magazine page
CSSthe look: colours, fonts, spacing, layoutthe design and the paint
JavaScriptthe behaviour: buttons that do thingsthe electricity that makes things move

HTML: structure

HTML is written with tags in angle brackets, such as <h1>. Most tags come in pairs. Tags can have attributes, such as href on a link. Here is the top part of this site's first page:

  • <meta name="viewport"> makes the page fit a phone screen.
  • <link rel="stylesheet"> loads the CSS file. <script> loads JavaScript.
  • lang="en-NZ" tells screen readers which language to use.

Good HTML uses semantic tags that say what each part is: <header>, <nav>, <main>, <footer>, <h1>–<h6>, <ul>, <table>. Screen readers and search engines rely on them.

Links: relative and absolute

A link such as href="physics.html" is relative: it means "the file called physics.html in the same folder". Relative links keep working when the whole site is moved to a different address. A link such as https://github.com/... is absolute.

CSS is a list of rules. Each rule has a selector (what to style) and properties (how). Here are the real rules for the coloured boxes on these pages:

A design process for a digital outcome

When you make a website or any digital outcome, follow these steps. You will often go back to an earlier step. That is normal and is called iteration.

  1. Understand the need. Who is it for? What do they want to do?
  2. Plan. Sketch the pages on paper. List the content.
  3. Build. Write HTML first, then CSS, then JavaScript.
  4. Test. Try it on a phone and a laptop. Ask someone else to use it.
  5. Improve. Fix problems. Then evaluate: did it meet the need?

Accessible and inclusive

  • Give every picture a short description in alt="...".
  • Use headings in order (one h1, then h2, and so on).
  • Make sure text has strong contrast with its background.
  • Do not rely on colour alone to give meaning.
  • Make sure everything works with the keyboard.
  • Use plain language and explain new words. Where it is right to, use te reo Māori alongside English.

Respect other people's work

Use pictures, sounds and code you made yourself, or that have a licence that lets you use them. Say where things came from. The pictures in this game are drawn by a small program, so there is nothing to copy.

Project 1: a ship trading card

Brief: make a web page with a "trading card" for one ship from the game. Use the ships table on the Ships page as your data.

Start with this skeleton, then add your own content and CSS:

<!DOCTYPE html>
<html lang="en-NZ">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Medic - ship card</title>
  <link rel="stylesheet" href="card.css">
</head>
<body>
  <main>
    <article class="card">
      <h1>Medic</h1>
      <img src="medic.png" alt="A white spaceship with a green cross">
      <p>Support ship that heals itself and its partner.</p>
      <table>
        <tr><th scope="row">Hull</th><td>95</td></tr>
        <tr><th scope="row">Ability</th><td>Repair Burst</td></tr>
      </table>
    </article>
  </main>
</body>
</html>

Success criteria: valid HTML with a sensible heading order; an alt description on the image; a CSS file with at least five rules, including one colour variable; looks good on a phone-sized window.

Project 2: all the ships with JavaScript

Once your card works, show all ships by using a loop, so you only write the card once:

const ships = [
  { name: "Phantom", hull: 80,  ability: "Cloak" },
  { name: "Medic",   hull: 95,  ability: "Repair Burst" }
];
const list = document.getElementById("cards");
for (const s of ships) {
  const card = document.createElement("article");
  card.className = "card";
  card.innerHTML = "<h2>" + s.name + "</h2><p>Hull: " + s.hull + "</p>";
  list.appendChild(card);
}

Extension: add a button that shows only ships with hull above 90 (a decision!).

Publishing with GitHub Pages

  1. Put your files in a GitHub repository (this site is in a folder called docs).
  2. Open the repository's Settings and choose Pages.
  3. Choose Deploy from a branch, pick main and the /docs folder, then save.
  4. After a minute your site is live at https://your-user.github.io/your-repo/.

Because every link on this site is relative, it works at that address with no changes. Open docs/site-config.js and type your user and repository name so the code links point to your repository.

Try it: view the source

In your browser, right-click this page and choose View page source. Find the <nav> and the <main>. Then open the browser's developer tools and change a colour in the CSS to see what happens. (Your change disappears when you reload.)

Check your understanding

1. What are the jobs of HTML, CSS and JavaScript?
HTML gives structure and content, CSS gives the look, JavaScript gives behaviour.
2. Why does this site use relative links?
They keep working wherever the site is hosted.
3. What is the point of the alt attribute?
It describes a picture for people who cannot see it, such as someone using a screen reader.
4. What is a media query used for?
To change the layout for different screen sizes, such as phones.
5. Which step of the design process comes after testing?
Improving (and evaluating) the outcome.
