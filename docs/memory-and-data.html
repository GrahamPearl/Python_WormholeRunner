2. Memory and data

How Python stores information, and which container to choose.

Learning intentions

  • see how Python stores values in memory
  • use lists, dictionaries, tuples and sets
  • understand that two names can point to the same object
  • understand the difference between a copy and a reference

Success criteria: I can…

  • choose the right data structure for a job
  • draw a memory diagram for a list and a dictionary
  • explain what happens when two variables share one list

Memory is a giant set of boxes

When a program runs, Python keeps its data in the computer's memory (RAM). Think of a variable as a name tag attached to a box that holds the value. If you write health = 100, the name health is attached to a box containing 100.

Lists: an ordered row of boxes

A list keeps many values in order. Items have a position number called an index, starting at 0. The game keeps its players in a list:

players = ["Pilot", "Medi"]
print(players[0])      # Pilot  (index 0 is the first item)
players.append("Kai")  # add to the end
print(len(players))    # 3

Arcade, the game library we use, gives us a special SpriteList that works like a list but is much faster to draw. That is why the game has rock_list, alien_list and bullet_list.

Dictionaries: look things up by name

A dictionary stores key: value pairs. Instead of remembering that "gravity" is item number 4, you just ask for "gravity". All of the game's settings live in one big dictionary, with dictionaries inside it:

A dictionary inside a dictionary is called nested. The class below finds a value using a dotted name such as "physics.gravity". It splits the name at the dots and steps down one level at a time:

Dictionaries are also how settings are saved to a file. The text format is called JSON, and Python can turn a dictionary into JSON and back again.

Tuples and sets

  • A tuple is like a list that cannot be changed once made. It is written with round brackets. Colours are tuples: red, green, blue, opacity.
  • A set holds unique items with no order and no repeats. It is perfect for "which keys are held down right now?"

Mutable or not?

Some things can be changed after they are made (mutable): lists, dictionaries, sets. Others cannot (immutable): numbers, strings, tuples. When you "change" a number, Python really makes a new one and moves the name tag.

Two names, one object: references

This idea catches out many programmers. If you write b = a for a list, you do not get a second list. You get a second name tag on the same box. Change the list through one name and the other name sees the change.

The game uses this on purpose. The window's key-press set is shared with the local player, so when the window records a key, the player sees it straight away:

Try it: make a copy

Open Python (or Thonny) and type:

a = [1, 2, 3]
b = a
b.append(4)
print(a)
c = list(a)      # a real copy
c.append(5)
print(a, c)

Predict the output of both print lines before you run it.

Check your understanding

1. Which data structure would you use to store a player's name, score and ship type together, and look each one up by name?
A dictionary, for example {"name": "Medi", "score": 120, "ship": "medic"}.
2. players = ["Pilot", "Medi"]. What is players[1]?
"Medi". Indexes start at 0.
3. Why is a set a good choice for the keys that are held down?
A key is either held or not, never twice, and order does not matter.
4. After b = a where a is a list, you add an item to b. Does a change?
Yes. Both names point at the same list.
5. How do you make a separate copy of a dictionary?
Use dict(original) or original.copy().
