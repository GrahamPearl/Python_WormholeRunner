5. The game loop

How the game runs, frame after frame.

Learning intentions

  • understand that a game is one big loop
  • explain what on_update, on_draw and dt are for
  • see how input events reach the code
  • understand why the order of drawing matters

Success criteria: I can…

  • describe the game loop in my own words
  • explain why movement is multiplied by dt
  • say what happens to a sprite drawn last

A game is a loop

A film is many still pictures shown quickly. A game is the same. About 60 times every second the game does three things: (1) check what the player pressed, (2) update the world, (3) draw a new picture. Each round is called a frame.

Our game uses the Arcade library. Arcade runs the loop for us and calls our methods at the right time:

MethodWhen it runsIts job
on_update(delta_time)every frameChange the world: move, collide, apply rules
on_draw()every frame, after updatePaint everything on the screen
on_key_press(key, mods)when a key goes downReact to a key press
on_key_release(key, mods)when a key comes upStop reacting to a key

Delta time: keeping speed fair

Computers run at different speeds. If a ship moves 5 pixels per frame, a fast computer (120 frames a second) would make it twice as fast as a slow one. The fix is to move by speed × time. Arcade tells us how long the last frame took. It is called delta_time, or dt for short.

x = x + speed * dt
# speed = 300 pixels per second, dt = 1/60 of a second
# so each frame the ship moves 300 * (1/60) = 5 pixels

The game also limits dt so that a long pause (like dragging the window) does not cause a huge jump:

What happens inside one update

Order matters

Hazards are updated before ships, because they change the ship's drift. Collisions are checked after everything has moved. Thinking about the order of steps is a big part of good program design.

Drawing: the painter's algorithm

Computers draw things one after another. Whatever is drawn last ends up on top, like layers of paint. So the game draws the background first and the ships last:

There are two cameras. The world camera can zoom out so you can see the whole map. The GUI camera never moves, so the score and health bars stay put.

Events: reacting to keys

Pressing a key is an event. Arcade calls on_key_press and our code decides what it means. Held keys are kept in a set. The ship's steering code asks if a key is in the set each frame.

Try it: slow motion

Check your understanding

1. About how many frames are drawn each second?
About 60.
2. Why do we multiply by dt when moving?
So the speed is the same on fast and slow computers.
3. The game draws the ship after the rocks. What is the result if a ship and a rock overlap?
The ship appears on top, because it was drawn last.
4. What is the job of on_draw? Should it change the ship's health?
It only paints the picture. The rules (like changing health) belong in on_update.
5. What is an event? Give an example.
Something that happens that the program can react to, such as a key press.
