3. Classes and objects

Blueprints for the things in the game.

Learning intentions

  • understand the difference between a class and an object
  • use attributes and methods
  • see how __init__ and self work
  • read the Player, Rock and Ship classes

Success criteria: I can…

  • explain a class using a real-life blueprint
  • name the attributes and methods of a class in the game
  • write a small class of my own

The blueprint idea

A class is a blueprint. An object is one thing built from the blueprint. The game has a Rock class (the blueprint) and many rock objects floating around, each with its own position, size and speed.

Parts of a class

  • Attributes are variables that belong to an object (its data).
  • Methods are functions that belong to an object (what it can do).
  • __init__ is the special method that runs when an object is made. It sets up the starting values. We call it the constructor.
  • self means "this particular object". Inside a method, self.health is this object's health.

A small class: Player

A player owns a ship, a set of weapons, a score and some credits. Read the code and find the attributes:

The attributes are made inside __init__ and reset. The method reset builds a fresh ship and score for a new game. The method revive brings a player back to life at half health.

Creating an object

You make an object by calling the class like a function: me = Player(1, "Pilot"). Python runs __init__ for you. Then me.score reads an attribute and me.revive() runs a method.

Another class: Rock

Notice self.mass = ROCK_SIZE_SCALE[size_class] ** 2. Bigger rocks have more mass, so they pull harder with gravity. A rule from physics is stored as one line in a class.

Properties: attributes that are worked out

Sometimes an attribute is not stored but calculated when asked. The ship has yes/no properties such as cloaked:

self.cloaked looks like a normal attribute, but it checks "is the ability a cloak, and is it still active?" every time.

Why use classes?

  • Keeps related data and actions together. A ship's health, speed and steering live in one place.
  • Makes copies easy. Make one ship or a hundred rocks with the same blueprint.
  • Makes changes safer. To change how rocks split, you only edit Rock.split.

Try it: write your own class

Write a tiny class in Python and make two objects from it:

class Alien:
    def __init__(self, name, health):
        self.name = name
        self.health = health

    def hit(self, damage):
        self.health = self.health - damage
        if self.health <= 0:
            print(self.name, "was destroyed!")

a = Alien("Zog", 30)
b = Alien("Blip", 10)
a.hit(15)
b.hit(15)

What prints? Which object has changed health? Add an is_alive method that returns True or False.

Check your understanding

1. What is the difference between a class and an object?
A class is the blueprint. An object is one thing made from it, with its own values.
2. What does self mean inside a method?
The object that the method is running on.
3. Name two attributes of a Rock.
For example size_class, vx, vy, hp, mass, kind.
4. When does __init__ run?
Automatically, when a new object is created.
5. Why does a bigger rock pull harder?
Its mass is larger, and the gravity rule multiplies by mass.
