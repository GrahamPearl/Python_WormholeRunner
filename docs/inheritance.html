4. Inheritance and design

How classes build on each other.

Learning intentions

  • understand inheritance: a class that builds on another
  • tell the difference between is-a and has-a relationships
  • understand polymorphism: one method name, many behaviours
  • read a class diagram

Success criteria: I can…

  • draw a simple class diagram
  • explain why Chaser and Sniper can both be used as an Alien
  • explain what super().__init__ does

Inheritance: "is a"

Many things in the game share the same jobs: they have a position, a picture and they play an animation. Rather than write that code again and again, one class holds it and others inherit it. A Ship is an AnimatedSprite. A Chaser is an Alien.

The top class, arcade.Sprite, comes from the Arcade library. It already knows how to hold a picture and draw it. AnimatedSprite adds one thing: it can flip through a sheet of pictures to make an animation.

Polymorphism: same name, different behaviour

Every alien has a method called think. Each kind of alien writes its own version. The game does not need to know which kind it has. It just calls think and each alien behaves in its own way. The word polymorphism means "many forms".

Compare how two aliens fill in think. The Drifter wobbles along a wave. The Chaser turns toward you.

Composition: "has a"

A Player is not a ship. A player has a ship, has weapons and has a score. When a class holds other objects as attributes, we call this composition. A good rule: use inheritance for is-a, composition for has-a.

Mixins: sharing a set of methods

The main game class got very big. To keep it tidy, the extra systems (credits, hazards, objectives, abilities and perks) live in a separate class called FeaturesMixin. The game class lists it as a parent so it can use all those methods:

The class has two parents. This is called multiple inheritance. A mixin is a parent that is never used alone.

Encapsulation: keeping things tidy

A class keeps its own data and the methods that change it together. Other code should ask the object to do things rather than reach in and change everything. In the game, a ship's ability timers are changed by ship methods, and the game asks ship.cloaked instead of checking the timers itself. A name that starts with an underscore, like _break_rock, is a hint: "this is for the class's own use".

Try it: draw it

Draw a class diagram for a new kind of alien called Bomber that drops bombs. Which class does it inherit from? Which method must it write? Which attributes will it need?

Check your understanding

1. Is a Player a Ship? Which relationship is it?
No. A player has a ship. That is composition, not inheritance.
2. What does super().__init__() do?
It runs the parent class's constructor so the parent's setup is done.
3. What is polymorphism? Give an example from the game.
Different classes with the same method name behaving differently, such as each alien's think method.
4. Why does ALIEN_CLASSES make the code simpler?
It looks up the class from a name, so one line can create any alien without a long chain of if statements.
5. Name one benefit of putting shared code in a parent class.
Less repeated code, and a fix in one place helps every child class.
