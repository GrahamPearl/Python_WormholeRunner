Teacher notes

Curriculum links, a unit plan, set-up and publishing.

About this resource

These pages help learners in Years 9 and 10 (about ages 13–15) understand programming by exploring a complete, working game. They are written in New Zealand English with short sentences, new words explained on first use, and a glossary. Every code box is real code from the game, linked to the same lines on GitHub.

Curriculum links

The resource is designed to sit in the Technology learning area of The New Zealand Curriculum, in the Digital Technologies and Hangarau Matihiko content, with web development as the context for the design and make tasks. Please confirm the alignment against the current documents on the Ministry of Education's Tāhūrangi curriculum site and your own school's programme, because the wording and progress outcomes are refreshed from time to time.

Assessment ideas

  • Formative: the 'Check your understanding' questions, 'Try it' tasks, and learners explaining a code box to a partner.
  • Summative (web development): a ship or alien page. Suggested criteria: valid, semantic HTML; a CSS file with variables and a media query; alt text and strong contrast; evidence of testing on two devices; a short evaluation saying what was improved and why.
  • Using AI helpers: ask learners to keep a short log: the prompt, what was wrong, how they fixed it, and what they learned. Learners should be able to explain any code they submit.
  • Invite whānau to a showcase where learners explain their pages.

Setting up

  1. Install Python 3.10 or newer from python.org (on Windows tick ‘Add Python to PATH’). Linux usually has it already.
  2. Unzip the game. On Windows double-click run_windows.bat. On Linux or Mac run ./run_linux.sh. The first run creates a private Python environment and installs Arcade and Pillow, so it needs internet access once.
  3. For learners who want to experiment, Thonny or Visual Studio Code both work well.
  4. School networks: two-player mode uses port 5555 on the local network only. Check with your network manager before using it. Single player needs no network.

Publishing this website

  1. Create a GitHub repository and upload the project (including the docs folder).
  2. In docs/site-config.js change YOUR-USER to your GitHub user name and check the repository name and branch.
  3. In the repository's Settings choose Pages, deploy from the main branch and the /docs folder.

If you change the game's code, run python tools/build_docs.py to refresh the snippets, line numbers, tables and diagrams.

Check that GitHub's age and privacy rules suit your school before asking learners to create their own accounts. Teachers can publish the shared site instead.

Differentiation

  • Support: use pages 1–3 with the 'Try it' tasks; let learners work in pairs; use the glossary; focus on changing numbers before changing code.
  • Extend: write a new alien class, add a new hazard, build the JavaScript card page, or complete the later tutorial prompts.

Safety and ethics

  • Credits are an in-game score only. The game never uses real money and collects no personal data. The profile is a small file on the learner's own computer.
  • Multiplayer is for people on the same local network. Discuss the safety points on page 11.
  • The pictures and sounds are generated by the program and may be replaced. If you use other people's media, check its licence. The Arcade and Pillow libraries are open-source; read their licences if you plan to share the game widely.
