13. Rebuild it: prompts

Sixteen short prompts that build the game step by step.

Learning intentions

  • learn to break a big project into small steps
  • write clear prompts that ask an AI helper for one feature at a time
  • test and check code before trusting it
  • compare my result with a finished example

Success criteria: I can…

  • write a prompt that names the language, the library and one clear goal
  • run, test and explain the code I am given
  • find the same feature in the real game code

You can rebuild the whole game in 16 small steps. Each step has a short prompt you can give to an AI helper (or use as a to-do list if you are writing the code yourself). Do the steps in order, because each one builds on the last.

How to work with an AI helper

A good routine for every step

  1. Paste the prompt, plus your current code if it is a later step.
  2. Read the answer. Can you explain each part? If not, ask the helper to explain it in simple words.
  3. Run it. If there is an error, copy the full message and ask what it means.
  4. Test against the ‘You should see’ line.
  5. Compare with the real code using the links. Your version does not need to match exactly. Different code that works is fine.
  6. Save your work before the next step.

Remember

The AI can make mistakes and may use old library versions. Always say Python 3.10+ and Arcade 3. You are responsible for understanding and checking what you hand in. Say clearly when you used an AI helper.

The 16 steps

1 A window and a menu

Using Python 3.10+ and the Arcade 3 library, write a program that opens a 1280x720 window with a dark blue background and shows the title 'Wormhole Runner'. Use a class that inherits from arcade.View for the menu, and a main() function that starts it.

You should see: A window with the title text.

Compare with the real code: main.py, game/menu_view.py

Challenge (by hand): Add a second menu item and move between items with the UP and DOWN keys.

2 A ship that turns

Add a Ship class that inherits from arcade.Sprite. Draw a simple triangle ship with the Pillow library and save it as a PNG in assets/images. Show the ship in the centre and make it turn left and right with the arrow keys.

You should see: A ship in the middle that rotates.

Compare with the real code: game/sprites.py, game/placeholder_art.py

Challenge (by hand): Make a different picture for the ship using Pillow's ImageDraw.

3 Speed and direction

Make UP and DOWN change the ship's speed and move the ship in the direction it faces using sine and cosine. Multiply movement by delta time so the speed is the same on every computer.

You should see: The ship flies where it points and speeds up and down.

Compare with the real code: game/sprites.py

Challenge (by hand): Add a maximum speed and make the ship stop at the screen edge.

4 Rocks and wrap-around

Add a Rock class that moves along diagonal lines at different sizes. Make rocks and the ship wrap around the screen edges using the modulo operator. Put the world size in a World class with wrap() and a delta() method that finds the shortest vector across the edge.

You should see: Rocks drifting across and reappearing on the opposite side.

Compare with the real code: game/world.py, game/sprites.py

Challenge (by hand): Draw a diagram showing why delta() is needed.

5 Collisions and health

Detect when the ship touches a rock using circle distance (math.hypot). Give the ship health, a health bar, and a short invincible time after a hit. End the game when health reaches zero and show Game Over.

You should see: Hitting a rock lowers health and flashes the ship.

Compare with the real code: game/game_view.py

Challenge (by hand): Make bigger rocks do more damage.

6 Gravity

Make every rock pull the ship using pull = G x mass / distance squared, with a softening distance and a maximum pull. Add the pull to a 'drift' velocity that slowly fades with damping. Use a function for the pull maths.

You should see: The ship curves toward big rocks.

Compare with the real code: game/physics.py, game/game_view.py

Challenge (by hand): Plot the pull against distance using a graph or a table.

7 Power-ups and wormholes

Add power-ups for speed, health and invincibility that appear at random places and run on timers shown on the screen. Add a wormhole that appears and disappears at random times. Flying into it starts the next level with more rocks.

You should see: Collectable items and a swirling wormhole that ends the level.

Compare with the real code: game/sprites.py, game/game_view.py

Challenge (by hand): Add a fourth power-up of your own.

8 Settings in a dictionary

Move every number (gravity, speeds, timings) into one nested dictionary of settings. Write a Config class that loads and saves it as JSON and finds values using dotted names such as 'physics.gravity'.

You should see: A config.json file you can edit to change the game.

Compare with the real code: game/config.py

Challenge (by hand): Add a new setting and use it in the game.

9 Sound

Write an AudioManager class that maps event names like 'crash' and 'powerup' to sound files in a settings dictionary. It must stay silent, not crash, if a file is missing. Add looping background music.

You should see: Sounds play when things happen, and music loops.

Compare with the real code: game/audio.py

Challenge (by hand): Add a sound for a new event.

10 Animated pictures and an editor

Load pictures as tile sequences: a sheet cut into frames of a given size and played at a given speed. Then add an in-game editor screen where I can choose image files and change the settings with the keyboard.

You should see: Animated sprites and an editor screen that saves your changes.

Compare with the real code: game/assets.py, game/editor_view.py

Challenge (by hand): Add one more setting to the editor.

11 Weapons

Add bullets fired with the space bar. Make a WeaponSystem class with several weapons chosen with the number keys. Give them different damage, speed, ammo and an unlock level. Include a spread shot and a homing missile that turns toward targets.

You should see: Different weapons and bullets crossing the screen.

Compare with the real code: game/weapons.py

Challenge (by hand): Design a new weapon and add it as key 7.

12 Aliens with AI

Create an Alien base class with a think() method. Make subclasses: a Drifter that moves along a wave, a Chaser that turns toward the ship, a Sniper that keeps its distance and leads its shots, and a Swarm that orbits the ship. Aliens can be shot and can shoot back.

You should see: Different enemies that behave in different ways.

Compare with the real code: game/aliens.py

Challenge (by hand): Make your own alien with a new movement idea.

13 Splitting rocks and a growing world

Make rocks split into smaller rocks when they are hit. Make the map bigger each level and zoom the camera out so all of it stays visible, easing smoothly to the new zoom.

You should see: Bigger levels and rocks that break into pieces.

Compare with the real code: game/sprites.py, game/game_view.py

Challenge (by hand): Change how fast the world grows.

14 Ships, abilities and credits

Describe each ship in a dictionary: price, health, speed multipliers, an ability and its own weapon. Add abilities (cloak, hyperjump, hyperspace, deflect, repair) on the SHIFT key with cooldowns. Add in-game credits earned by playing, a Hangar shop screen and a profile.json file that saves them.

You should see: A shop where credits buy ships with different abilities.

Compare with the real code: game/game_features.py, game/profile.py, game/hangar_view.py

Challenge (by hand): Add a new ship using only a settings entry.

15 Hazards, objectives and perks

Add an Expedition mode with hazards (nebula, black hole, ion storm, solar flare), different rock types, objectives that must be completed before the wormhole opens, and a choice of one of three random perks after each level. Keep a Classic mode without them.

You should see: A game mode that adds new rules each level.

Compare with the real code: game/game_features.py, game/hazards.py, game/perks.py

Challenge (by hand): Invent a new hazard class.

16 Multiplayer on a local network

Add two-player multiplayer on a local network. One player hosts and runs the whole game; the other sends key presses and draws snapshots using JSON over TCP. Use a UDP broadcast so players can find games, and also allow typing an IPv4 address.

You should see: Two computers flying on the same map.

Compare with the real code: game/net.py, game/client_view.py, game/net_views.py

Challenge (by hand): Write a short safety poster for online games.

When your result is different

Your game will not look exactly like this one, and that is good. If something does not work: re-read your prompt for missing details, make the step smaller, or ask the helper to add only the missing part. Make sure your names for things are clear so you can come back to the code later.
