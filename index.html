Student Project Specifications

Brief: Design, develop, and test an interactive 2D endless-runner / spatial navigation game in Python where the player pilots a vessel through destabilising wormhole hazards, managing velocity, collision boundaries, and progressive difficulty.

Core Gameplay Mechanics

Foundational systems required for a Minimum Viable Product (MVP):

  • Real-Time Game Loop: Fixed-timestep frame updates handling input polling, state transitions, and screen rendering.
  • Player Kinematics: Responsive directional movement with boundary clamping and smooth velocity control.
  • Dynamic Obstacles: Procedural spawning of wormhole walls, debris, or energy gates with scaling speed.
  • Collision & Scoring: Bounding-box or distance-based hit detection, lives/shield tracking, and live score counters.

Technical & Code Standards

Software engineering conventions expected in student submissions:

  • Modular Decomposition: Separation of game configuration, entity logic, rendering, and main execution loop.
  • Data Structures: Effective use of lists, dictionaries, or classes to manage active hazards and player state.
  • Readable Conventions: PEP 8 naming, descriptive docstrings, and meaningful inline comments explaining logic.
  • Version Control: Incremental commits tracking feature branches, bug fixes, and refactoring milestones.

Testing & Extension Pathways

Iterative validation and stretch goals for Merit/Excellence outcomes:

  • Triangulated Testing: Documented test cases covering expected, boundary, and invalid user inputs.
  • State Management: Clean transitions across Start Menu, Active Play, Pause, and Game Over screens.
  • Persistent High Scores: File I/O (JSON/CSV) to save and retrieve leaderboard records across sessions.
  • Audio & Visual Feedback: Particle trails, screen shake, and sound effects triggered by game events.
